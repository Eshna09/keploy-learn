
# Test a Go API with Keploy

Learn how to capture real API interactions and replay them as automated tests using Keploy, Go, and Docker.

---

## What you'll build

You'll run a Go URL-shortener backed by MySQL, record live API traffic, and watch Keploy turn those requests into automated regression tests — no manual test-writing needed.

> **New here?** Read the prerequisites first, then follow the steps in order. Each step builds on the one before it.

---

## How the workflow works

Traditional tests require you to write inputs and expected outputs by hand. Keploy skips that — it watches your running app, records real API interactions, and saves them as reusable test cases.

When you replay, Keploy resends those recorded requests and checks whether the responses still match. If something changed unexpectedly, you'll know immediately.

> **Keep in mind:** Replay only validates the scenarios you recorded. It doesn't cover every possible behavior — just the ones you captured.

---

## Before you begin

Make sure the following are ready before you start:

| Requirement | How to check |
|:--|:--|
| Go is installed | `go version` |
| Docker Desktop is running | Open Docker Desktop and confirm it shows "Running" |
| WSL 2 integration is enabled | Docker Desktop → Settings → Resources → WSL Integration |
| Keploy CLI is installed (Ubuntu) | `keploy version` |
| `samples-go` repo is cloned | `ls` should show the project folder |

> **Use your Ubuntu terminal** for all commands below. Run everything from the root of the cloned `samples-go` repository.

### Troubleshooting common issues

- **`keploy: command not found`** → Install the Keploy CLI and reopen your terminal
- **`docker: command not found`** → Install Docker Desktop and start it
- **Port already in use** → Stop the other service using that port, or change the exposed port number
- **Permission denied** → Check your Docker access in WSL
- **Database connection error** → Make sure MySQL is running and reachable from the app container

## The application endpoints

The sample URL-shortener has three endpoints:

| Method | Endpoint | What it does |
|:--|:--|:--|
| `POST` | `/create` | Create a shortened link |
| `GET` | `/all` | List all saved links |
| `GET` | `/links/{id}` | Get a specific link by ID |

You'll use `/create` and `/all` during recording.

---

## Step 1 — Start recording

Open your **Ubuntu terminal**, go to the project root, and run:

```bash
keploy record -c "docker run -p 8080:8080 --rm --name url-short --network keploy-network url-short" --container-name "url-short" --buildDelay 60
```

This starts Keploy in record mode and watches the running Docker container. Wait until you see a message saying the app is ready before moving to Step 2.

---

## Step 2 — Send a request to create a link

While recording is active, open a **second Ubuntu terminal** and run:

```bash
curl -X POST http://localhost:8080/create \
  -H "Content-Type: application/json" \
  -d '{"link":"https://github.com"}'
```

You should get back a shortened URL in the response.

---

## Step 3 — Fetch all saved links

In the same second terminal, run:

```bash
curl http://localhost:8080/all
```

This lists all saved links and gives Keploy a second interaction to record.

---

## Step 4 — Stop recording

Go back to your **first terminal** (where Keploy is running) and press:

```
Ctrl + C
```

Keploy will save the recorded interactions as test files. You should see output like:

```text
✅ Captured request for POST /create
✅ Captured request for GET /all
✅ Test case generated
```

---

## Step 5 — Inspect the generated tests

After stopping, Keploy creates test files in the `keploy/tests/` folder:

- `keploy/tests/post-create-1.yaml` — the POST request you sent
- `keploy/tests/get-all-1.yaml` — the GET request you sent

Each file contains the recorded request, the expected response, and any relevant mocks.

> The saved test report for this run shows **2 successful tests** and **0 failures**.
>
> ```text
> 2 successful tests
> 0 failed tests
> ```

---

## What to remember

- You don't write tests manually — Keploy captures them from real traffic
- Replaying tests helps you catch regressions before they reach production
- Tests only cover what you recorded — make sure to capture all important scenarios
- If something fails, check the terminal output, container status, open ports, and the generated YAML files before changing any code
